# 如何写论文-Methods

> 📣 Methods 应当是论文中相对最好写的部分，因为它主要回答一个问题：
>
> **本文的方法到底是怎么做的？**
>
> 对于 AI 论文而言，Methods 通常需要把以下内容讲清楚：
>
> 1. **方法的核心思想。**
>
> 2. **问题定义和符号系统。**
>
> 3. **模型结构或算法流程。**
>
> 4. **关键模块的设计动机。**
>
> 5. **公式、目标函数、推导过程。**

## 推荐采用“总分结构”

Methods 一般适合采用总分结构：

1. Overview：先总体介绍方法。

2. Problem Formulation：定义问题和符号。

3. Method Details：分模块讲方法。

4. Training / Optimization：讲训练目标和优化方式。

5. Inference / Deployment：讲测试或使用阶段如何运行。

这种结构的好处是，读者先看到方法全貌，再逐步进入细节，不会一开始就被公式、符号和模块名称淹没。

## 先写 Overview

Methods 开头通常应先写一段 Overview，用来介绍方法的核心思想。

Overview 不需要写太多细节，而是要回答：

- 本文方法要解决什么问题？

- 方法的基本出发点是什么？

- 方法由哪些主要模块组成？

- 每个模块大致负责什么？

- 整体流程如何从输入走到输出？

**Overview 应该和方法的主图配合使用，主图负责让读者“看见方法”，Overview 负责让读者“理解这张图”。**

## 单独写 Problem Formulation

AI 论文通常会出现很多字母、符号、变量、集合、函数和下标。如果不提前定义清楚，读者后面读公式会非常吃力。

因此，建议单独写一节 Problem Formulation。

这一节需要说明：

- 输入是什么。

- 输出是什么。

- 训练数据如何表示。

- 模型或函数如何表示。

- 目标是什么。

- 关键变量、集合、索引和符号分别代表什么。

## 所有公式都要被解释

Methods 中出现的所有公式，都应该满足三个要求：

1. **公式前要说明为什么需要这个公式。**

2. **公式后要解释公式中每个关键符号。**

3. **公式后要说明这个公式在方法中起什么作用。**

**不要突然扔出一个公式，让读者自己猜它的意义。**

推荐结构是：

先写一句引导：

> To model ..., we define ...

然后给出公式，

公式之后解释：

> where ... denotes ..., and ... represents ....

最后说明作用：

> This objective encourages the model to ...

尤其需要注意：

- 每个符号第一次出现时必须定义。

- 同一个符号不要在不同地方表示不同含义。

- 不要使用过多没有必要的下标。

- 公式应和正文逻辑绑定，而不是为了显得“数学化”。

## 按模块展开 Method Details

Overview 之后，正文应按模块展开方法细节。

比如，如果方法由三个模块组成，就可以写成：

1. Module A: ...

2. Module B: ...

3. Module C: ...

每个模块可以按下面顺序写：

1. 这个模块解决什么问题。

2. 这个模块接收什么输入。

3. 这个模块如何处理输入。

4. 这个模块输出什么。

5. 为什么这样设计。

不要只写模块名称和公式。读者真正需要理解的是：这个模块在整个方法中承担什么功能。

## 算法可以用伪代码辅助说明

如果方法流程较复杂，可以加入 Algorithm 或 Pseudocode。

伪代码不应替代正文解释。正确做法是：

1. 正文先解释算法目的。

2. 伪代码展示完整流程。

3. 正文再解释关键步骤和设计理由。

伪代码中的变量也要和正文中的符号保持一致。

## 写清楚本文的 novelty

**Methods 不能只描述方法，还要让读者知道：本文的新意在哪里。**

可以在每个关键模块中说明：

- 这个模块和已有方法有什么不同。

- 为什么需要这个设计。

- 它解决了什么具体问题。

- 如果没有这个模块会怎样。

但要注意，Methods 中的 novelty 说明应当简洁，详细比较和效果证明应放在Experiments 中。
